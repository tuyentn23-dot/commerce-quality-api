Exact duplicate detection API for JSON batches

Find exact duplicate candidates by selected scalar keys in up to 500 JSON records. Returns review groups and skipped indices, with no deletion or merging.

Try the free BASIC plan on RapidAPI

Find exact duplicate candidates before a CRM, order or ETL import. Send 1–500 JSON records and choose 1–8 top-level scalar fields. The maximum request payload is 1 MB. Review the returned candidates before importing; the API never deletes or merges records.

Single keys and compound keys

Multiple selected fields use AND matching: all values must match. Strings are trimmed. Enable casefold: true to compare strings without case, including Unicode case folding. Types remain distinct: true, 1, 1.0 and "1" do not collide.

Incomplete keys are skipped

Missing, null, blank, object and array key values skip the record. Groups and skipped indices are zero-based. Nested field paths and fuzzy names are unsupported. This checks only the submitted batch, not records already in a CRM.

Normalize before comparing contacts

If phone or email formatting differs, first use VN Contact Cleaner, then compare selected normalized values. Shared household numbers and role mailboxes may describe different people: matching keys are candidates, not proof of identical identity.

Request example

Set RAPIDAPI_KEY to your own consumer key. Copy the host from your RapidAPI playground if your subscription shows a different host. No provider secret is needed. This example uses a POSIX shell.

curl --request POST \
  --url 'https://batch-duplicate-candidates.p.rapidapi.com/v1/records/duplicate-candidates' \
  --header 'Content-Type: application/json' \
  --header "X-RapidAPI-Key: $RAPIDAPI_KEY" \
  --header 'X-RapidAPI-Host: batch-duplicate-candidates.p.rapidapi.com' \
  --data '{"records":[{"order_id":" A-001 "},{"order_id":"A-001"},{"order_id":""},{"order_id":"B-002"}],"key_fields":["order_id"],"casefold":false}'

What if a request fails?

401: check your RapidAPI key and subscription; do not call the provider backend directly. 413: reduce the payload below 1 MB. 422: check required fields and batch limits. Timeouts can occur during free-hosting cold starts.
