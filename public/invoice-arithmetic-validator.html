Invoice arithmetic validation API

Check invoice totals, subtotals and line items after OCR. Decimal arithmetic, mismatch details and a free RapidAPI trial.

Try the free BASIC plan on RapidAPI

Use this API after invoice extraction and before a reviewed accounting import. It checks total = subtotal + tax + shipping - discount, supplied line totals against subtotal, and each line's quantity × unit price.

For example, subtotal 100 plus tax 10 should produce total 110. A supplied total of 120 returns a mismatch with the expected amount and difference.

Amounts, rounding and missing values

Send decimal strings. Default tolerance is 0.01 in the units you supply; choose a tolerance for your workflow. Up to 200 lines and 1 MB per request. Do not turn missing extraction fields into zero: review them first.

Arithmetic consistency does not establish invoice authenticity, tax compliance, vendor identity, fraud detection or currency conversion. Consistently wrong inputs can pass.

Connect extraction to validation

Map the extractor's invoice.tax_amount to validator tax, and each line_items[].amount to lines[].line_total. Require subtotal and total before calling the validator. See the Python pipeline and n8n mapping guide. The n8n template has not been tested in a live n8n installation.

Choose this check when

You already have structured invoice amounts and need a small HTTP step that reports arithmetic mismatches before a human reviews an import. It can accompany your current extraction provider; using our extractor is optional.

If you only need one fixed calculation and can maintain code in your workflow, a local Decimal calculation may be sufficient. This service adds a consistent request contract and field-level results. It does not check purchase orders, bank accounts, supplier records or previously submitted invoices. Credit notes with negative amounts are unsupported.

Review policy

  1. Missing or uncertain extraction values: stop for review before validation.
  2. Arithmetic mismatch: show the affected field, expected amount and difference to the reviewer.
  3. Arithmetic passes: continue other checks; this is not permission to pay or post automatically.

Request example

Set RAPIDAPI_KEY to your own consumer key. Copy the host from your RapidAPI playground if your subscription shows a different host. No provider secret is needed. This example uses a POSIX shell.

curl --request POST \
  --url 'https://invoice-arithmetic-validator.p.rapidapi.com/v1/invoices/validate' \
  --header 'Content-Type: application/json' \
  --header "X-RapidAPI-Key: $RAPIDAPI_KEY" \
  --header 'X-RapidAPI-Host: invoice-arithmetic-validator.p.rapidapi.com' \
  --data '{"subtotal":"100","tax":"10","shipping":"0","discount":"0","total":"120","lines":[{"quantity":"2","unit_price":"50","line_total":"100"}]}'

What if a request fails?

401: check your RapidAPI key and subscription; do not call the provider backend directly. 413: reduce the payload below 1 MB. 422: check required fields and batch limits. Timeouts can occur during free-hosting cold starts.
